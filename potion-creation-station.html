Solo Project

The Potion Creation Station

A console-based inventory system for an RPG-style potion shop, built around a self-balancing Red-Black Tree so insertions, deletions, and sorted listings stay fast as the shop's stock grows. Potions carry Strength, Speed, and Health stats, with flexible sorting, search, and a guided walkthrough interface.

The Problem

Why a Red-Black Tree

In many RPGs, players collect potions that boost stats — managing that inventory efficiently (sorting it, finding the strongest item) is a real-world case for the right data structure. A plain list means re-sorting on every change; an unbalanced BST can degrade to O(n) on the wrong input. A Red-Black Tree avoids both.

  • O(log n) Guaranteed — Self-balancing via rotations and recoloring on every insert/delete, so performance never degrades as the inventory grows.
  • Always Sorted — An in-order traversal returns potions already sorted by whichever stat is active — no separate sort step.
  • Swappable Sort Key — Sort key is a std::function, so switching between Total / Strength / Speed / Health rebuilds the ordering without duplicating logic.

How It Works

Under the hood

  • Potion — Struct holding name, strength, speed, health, plus a totalStats() helper.
  • Node — Tree node storing a Potion, its red/black color, and parent/left/right pointers.
  • RedBlackTree — insert, remove, search, inorder, and clear, with move semantics (copying is disabled on purpose — only one tree should own a given set of nodes).
  • Input Validation — Menu choices are numeric-only, potion names can't be empty, and stats are capped 0–100,000, all enforced before anything touches the tree.
  • 6-Option Menu — Add, Display, Search, Delete, Clear, Change Sort, Quit — each with its own success/failure message.

Reflection

Challenges & what I learned

  • Rotation & Recoloring — Getting insertion fix-ups right is the classic hard part of a Red-Black Tree from scratch; one missed case breaks the balance guarantee.
  • Defensive Input Handling — Every menu path had to survive non-numeric input, empty names, and out-of-range stats without crashing.
  • Move Semantics in C++ — Explicit move constructor/assignment, with the copy constructor deleted outright, to keep tree ownership unambiguous.
